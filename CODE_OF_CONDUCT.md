# Code of Conduct

## Purpose

This project is a collaborative research and engineering project for the AI Conquer Module 3 healthcare-risk-prediction study. The team aims to maintain a respectful, evidence-based, and reproducible working environment.

## Expected Behavior

Contributors are expected to:

- communicate respectfully and assume good intent;
- discuss technical disagreements using code, experiments, sources, or documented requirements;
- keep Jira tasks, implementation scope, and Definition of Done clear;
- document dataset sources, licensing or usage conditions, known limitations, and validation decisions;
- keep report claims consistent with the current code, configuration, and generated results;
- review changes that affect the research questions, data pipeline, model comparison, evaluation, or report;
- give constructive feedback focused on the work rather than the person;
- acknowledge relevant contributions and preserve the provenance of external sources.

## Collaboration Workflow

Work should normally be connected to a Jira task or epic. A change is considered ready when its stated Definition of Done is satisfied, the affected code or report content is checked, and relevant validation evidence is available.

For changes to shared research components:

1. Describe the scope and expected outcome in Jira or the pull request.
2. Keep commits focused and use a clear message.
3. Run the relevant tests, syntax checks, or report build.
4. Update documentation or report text when behavior or methodology changes.
5. Request review from the relevant role, such as Tech Lead, Model, Data, Pipeline, or QA/Reviewer.

Dataset changes should include the source, schema checks, preprocessing implications, and known limitations. Model or experiment changes should explain their effect on configuration, metrics, reproducibility, and report conclusions.

## Unacceptable Behavior

The following behavior is not acceptable:

- harassment, discrimination, intimidation, or personal attacks;
- abusive, threatening, or deliberately humiliating language;
- presenting another person's work, code, analysis, or writing as one's own;
- hiding changes that materially affect data, experiments, metrics, or report claims;
- altering or selectively reporting results to create a misleading conclusion;
- sharing restricted data, credentials, or private team information;
- intentionally disrupting the repository, Jira workflow, or review process.

## Reporting Concerns

Concerns should be reported privately to the Team Leader or Tech Lead through the team's agreed communication channel. If the concern involves that person, contact another trusted team member or the QA/Reviewer. Reports should include the relevant Jira issue, pull request, commit, message, or other evidence when available.

The team will handle reports discreetly, review the available evidence, and take proportionate action. Retaliation against a person who raises a concern in good faith is not acceptable.

## Scope

This Code of Conduct applies to project discussions, Jira tasks, GitHub issues and pull requests, code reviews, report reviews, meetings, and other collaboration spaces used for this project.
